# Pinned to what zeus-core actually runs, captured from its image with
# `pip freeze` on 2026-09-18. Used as a pip CONSTRAINTS file (-c), so it
# fixes versions without installing anything extra.
#
# Why: the verify image resolves '>=' at build time, so it drifts from the
# deployed stack on every rebuild. A gate that measures a different library
# set than production is measuring the wrong thing, and the drift shows up
# as an unexplained metric move rather than as an error.
#
# Regenerate after changing requirements.txt or rebuilding zeus-core:
#   docker run --rm --entrypoint sh zeus-zeus-core:latest -c 'pip freeze' \
#     | grep -vE '^(-e|zeus)' > docker/verify/constraints-deployed.txt
#
# Note: qdrant-client here is 1.19.0 against a 1.17.0 server. That skew is
