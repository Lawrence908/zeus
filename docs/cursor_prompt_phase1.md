## What to Build

### 1. Session Layer — `core/sessions.py` (NEW FILE)

**Purpose:** Multi-turn conversation continuity across chat and voice paths. Sessions persist across requests, support rolling summaries for long conversations, and provide the conversation history that the query engine needs.

**Requirements:**

```python
# core/sessions.py

class Session:
    """Single conversation session."""
    id: str                          # UUID
    created_at: float                # Unix timestamp
    updated_at: float                # Unix timestamp
    turns: list[Turn]                # Full turn history
    summary: str | None              # Rolling summary of older turns (generated by LLM)
    metadata: dict[str, Any]         # Extensible (source="chat"|"voice", user_id, etc.)

class Turn:
    """One user→assistant exchange."""
    user: str
    assistant: str
    timestamp: float
    context_sources: list[str]       # Which memory sources were used
    latency_ms: int

class SessionManager:
    """Manages session lifecycle. Injected into app.state during lifespan."""

    def __init__(self, storage: SessionStorage):
        ...

    async def create(self, metadata: dict | None = None) -> Session: ...
    async def get(self, session_id: str) -> Session | None: ...
    async def append_turn(self, session_id: str, turn: Turn) -> Session: ...
    async def get_context_window(self, session_id: str, max_turns: int = 10, max_tokens: int = 4096) -> str:
        """
        Build the conversation context for the LLM.
        If session has >max_turns, use the rolling summary + recent turns.
        Token budget: summary gets 1/3, recent turns get 2/3.
        """
        ...
    async def generate_summary(self, session_id: str) -> str:
        """
        Summarize older turns into a rolling summary.
        Called when turn count exceeds a threshold (e.g., 20 turns).
        Uses the same LLM provider as chat (Claude dev / Ollama prod).
        """
        ...
    async def list_recent(self, limit: int = 10) -> list[Session]: ...
    async def delete(self, session_id: str) -> bool: ...
```

**Storage backend:** Start with `InMemoryStorage` (dict-backed, same as current behavior but structured). Define a `SessionStorage` protocol so SQLite or file-based storage can be swapped in later without touching `SessionManager`.

```python
class SessionStorage(Protocol):
    async def save(self, session: Session) -> None: ...
    async def load(self, session_id: str) -> Session | None: ...
    async def list_recent(self, limit: int) -> list[Session]: ...
    async def delete(self, session_id: str) -> bool: ...
```

**Rolling summary trigger:** When a session exceeds 20 turns, summarize the oldest turns (keeping the most recent 10 intact) and store the summary. The context window method should prepend the summary before recent turns.

**Key constraint:** Sessions must work for both chat and voice paths. The `metadata.source` field distinguishes them but the session logic is identical.

### 2. Query Engine — `core/query.py` (NEW FILE)

**Purpose:** The brain of Zeus. Takes a user message + session context → retrieves memories → builds prompt → calls LLM → returns response. Extracted from `chat.py` so voice pipeline can reuse it.

**Requirements:**

```python
# core/query.py

class QueryEngine:
    """
    Central query handler for Zeus.
    Used by both chat routes and (future) voice pipeline.
    """

    def __init__(self, memory, session_manager: SessionManager):
        self.memory = memory
        self.sessions = session_manager

    async def query(
        self,
        message: str,
        session_id: str | None = None,
        *,
        use_context: bool = True,
        max_tokens: int = 512,
        stream: bool = False,
    ) -> QueryResult:
        """
        Full query pipeline:
        1. Get or create session
        2. Search mnemosyne for relevant memories
        3. Get profile facts for baseline context
        4. Build system prompt (profile + memories + session history)
        5. Call LLM (Claude dev / Ollama prod)
        6. Append turn to session
        7. Return structured result
        """
        ...

    async def query_stream(
        self,
        message: str,
        session_id: str | None = None,
        *,
        use_context: bool = True,
        max_tokens: int = 512,
    ) -> AsyncGenerator[str, None]:
        """
        Streaming variant — yields token chunks.
        Same pipeline as query() but streams the LLM response.
        """
        ...


class QueryResult(BaseModel):
    session_id: str
    assistant_message: str
    context_sources: list[str]
    latency_ms: int
    model_used: str               # Which model actually handled it
    token_estimate: int           # Approximate tokens in response
```

**System prompt construction:**

```
You are Zeus, a personal AI assistant for Chris. You have access to Chris's
personal knowledge base and conversation history.

## Profile
{profile_facts — 3-5 stable facts about Chris from mnemosyne}

## Relevant Context
{memory search results — top 5 memories matching the query}

## Conversation
{rolling summary if exists}
{recent turns from session}

Be concise, direct, and helpful. Use markdown when it aids clarity.
If you don't know something, say so — don't fabricate.
```

**LLM provider selection:** Extract `_run_llm()` and `_chat_use_claude()` from the current `chat.py` into `query.py`. Support both completion and streaming for both providers (Anthropic streaming uses `stream=True` on `messages.create()`; Ollama streaming uses `"stream": True` in the generate payload and returns NDJSON lines).

Add `SessionManager` and `QueryEngine` to the app lifespan:

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.http_client = httpx.AsyncClient()
    app.state.memory = get_memory_client()
    app.state.voice_hub = VoiceStateHub()

    # NEW: Session + Query engine
    storage = InMemoryStorage()
    app.state.session_manager = SessionManager(storage)
```
