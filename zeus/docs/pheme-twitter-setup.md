# Pheme Twitter Setup

One-time setup to let Pheme post digests to X/Twitter. Subsystem overview:
[`pheme.md`](pheme.md). Everything happens in three places: the X developer
portal, `zeus/.env`, and one terminal command.

## What goes where

| Value | Where it comes from | Where it goes |
|---|---|---|
| `TWITTER_OAUTH2_CLIENT_ID` | X developer portal, app "Keys and tokens" -> OAuth 2.0 Client ID | `zeus/.env` |
| `TWITTER_OAUTH2_CLIENT_SECRET` | Same page -> Client Secret (only shown once) | `zeus/.env` |
| Access + refresh tokens | Generated by `scripts/twitter_oauth_setup.py` | `zeus/data/pheme/twitter_token.json` (automatic - never edit) |
| `PHEME_TWITTER_ENABLED=1` | You, after the script succeeds | `zeus/.env` |
| `PHEME_TWITTER_AUTOPOST` | Leave `0` - Telegram **Tweet it** stays the gate | `zeus/.env` |

The poster (`zeus/integrations/twitter/poster.py`) reads the token state file
first and rotates it on every refresh, so `.env` never holds tokens - only the
app credentials. `TWITTER_OAUTH2_ACCESS_TOKEN` / `_REFRESH_TOKEN` in
`.env.example` exist as a manual fallback; the script path leaves them blank.

## Step 1 - X developer app (5 minutes, in a browser)

1. [developer.x.com](https://developer.x.com) -> sign in as the account that
   should tweet -> create a project + app (Free tier is enough: it allows
   ~500 posts/month, and Pheme posts at most 4 tweets per daily digest and
   only on Telegram approval).
2. In the app's **User authentication settings**:
   - App permissions: **Read and write**
   - Type of app: **Web App, Automated App or Bot** (confidential client)
   - Callback / Redirect URL: `http://localhost:8971/callback`
   - Website URL: anything real (e.g. `https://chrislawrence.ca`)
3. On **Keys and tokens**, copy the **OAuth 2.0 Client ID and Client Secret**.
   (Not the API Key/Secret pair and not the Bearer Token - those are OAuth 1.0a
   / app-only credentials and the poster does not use them.)

## Step 2 - .env

```bash
# in zeus/.env
TWITTER_OAUTH2_CLIENT_ID=<from step 1>
TWITTER_OAUTH2_CLIENT_SECRET=<from step 1>
```

## Step 3 - authorize once

```bash
cd ~/zeus
.venv/bin/python scripts/twitter_oauth_setup.py
```

The script prints an authorization URL. Open it in a browser logged in as the
tweeting account, approve, and paste the resulting redirect URL back into the
terminal (the browser will show "connection refused" on localhost - that is
expected; the URL in the address bar is what matters). The script exchanges the
code, verifies the identity via `/users/me`, and writes
`zeus/data/pheme/twitter_token.json`. From then on the poster refreshes and
rotates tokens automatically (access tokens expire in ~2h; the refresh token
rotates on every use and requires the `offline.access` scope the script
requests).

## Step 4 - enable and verify

```bash
# in zeus/.env
PHEME_TWITTER_ENABLED=1
# PHEME_TWITTER_AUTOPOST stays 0: posting only happens on Telegram "Tweet it"

docker compose up -d zeus-core   # recreate so env changes apply
```

Verification without posting: the next digest push to Telegram will carry the
**Tweet it / Skip** buttons. For a live end-to-end test that actually posts,
either tap **Tweet it** on a digest, or run the gated MCP tool directly:

```bash
.venv/bin/python -c "
import asyncio
from dotenv import load_dotenv; load_dotenv('.env')
from zeus.integrations.twitter.poster import post_news_thread
print(asyncio.run(post_news_thread('Pheme wiring test - hello from Zeus.')))"
```

Every tweet passes the Aegis `pheme` policy inside `post_news_thread` before
send; there is no ungated path.

## Troubleshooting

- **`unauthorized_client` at token exchange**: the app's callback URL does not
  exactly match `http://localhost:8971/callback`, or the app type is not a
  confidential client while a secret was sent (or vice versa).
- **`403` on posting**: app permissions are Read-only - flip to Read and write
  in User authentication settings, then re-run the script (a permission change
  invalidates prior tokens).
- **`token refresh failed` in logs later**: the refresh token was revoked or a
  concurrent refresh raced the rotation. Re-run `scripts/twitter_oauth_setup.py`.
- **Aegis rejects a tweet**: intended behavior - see
  `zeus/safety/policies/pheme.yaml` for the rules (injection artifacts,
  credentials, personal identifiers, trading-advice phrasing).
